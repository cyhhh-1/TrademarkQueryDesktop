## 1. 产品是什么

Windows 本地桌面客户端。员工选择 XLSX 后，程序在本机 **Microsoft Edge** 里查询国家知识产权局商标网（CNIPA），把结果字段和证据截图写入一份新的结果 XLSX。

支持两种表格：

| 模板识别依据 | 业务 | 主要写入 |
| --- | --- | --- |
| 表头没有「是否唯一性」 | 商标申请查询 | 申请人、专用权期限、详情页整页截图 |
| 表头含「是否唯一性」 | 商标是否唯一性 | 是/否/未检索到同名商标/需人工复核，以及全部同名行的拼接截图 |

硬边界：

- 完全本机运行，无服务端、无数据库、无自动更新、无用户账号体系。
- 不读取、不保存、不自动填写 CNIPA 账号密码和验证码；员工在专用 Edge 里自己登录。
- 不修改员工选中的原始 XLSX。
- 同一台电脑同一时间只允许一个 Worker / 一个商标任务。
- 不打包 Chromium；使用机器已安装的 Edge。
- 不使用 WebDriver，也不加 `--enable-automation`。

网站入口固定为：`https://wcjs.sbj.cnipa.gov.cn/`

## 2. 架构

```text
员工
  │
  ▼
Vue 3 界面  ──invoke──►  Tauri 2（Rust）
                              │  stdin/stdout NDJSON
                              ▼
                     Python Worker（sidecar）
                              │
              ┌───────────────┴────────────────┐
              │                                │
     UI Automation（登录检测、        本机回环 CDP（截图、
     把窗口移回屏幕给员工）           同标签页查询、翻页）
              │                                │
              └───────────────┬────────────────┘
                              ▼
              专用可见 Microsoft Edge
              用户数据目录独立，不碰员工日常 Edge
                              ▼
              国家知识产权局商标查询网站
```

三层职责：

| 层 | 目录 | 职责 |
| --- | --- | --- |
| 界面 | `apps/desktop/src/` | 选文件、状态、进度、暂停/继续、另存为、模型设置 |
| 桌面壳 | `apps/desktop/src-tauri/` | 窗口、文件对话框、通知、拉起/停止 Worker、读写 `settings.json` |
| Worker | `worker/src/trademark_worker/` | 认模板、开 Edge、查网站、截图、写 XLSX、检查点 |

通信约定：

- 协议版本 `protocol: 1`，一行一个 JSON。
- 标准输出只允许协议事件；诊断走 stderr 或本地日志，不要把 Cookie、密码、验证码打进日志。
- Worker 启动后先发 `hello`，带 `worker_version`。
- 桌面端监听 Tauri 事件名 `worker-event`。
- 关闭窗口时先发 `shutdown`，最多等 35 秒，超时再杀进程，否则专用 Edge 会残留。

Worker 命令：`inspect_file`、`open_browser`、`connect_browser`、`browser_status`、`start`、`pause`、`resume`、`cancel`、`shutdown`。

开发态 Worker 走 `worker\.venv\Scripts\python.exe -m trademark_worker`；安装包走 sidecar `trademark-worker.exe`。

## 4. 员工操作对应的程序行为

1. **选 XLSX** → `inspect_file`。只接受 `.xlsx`。按标准化表头识别模板，不依赖固定列号。
2. **打开商标网站** → `open_browser`。启动或接回专用 Edge，打开 CNIPA 首页，窗口拉到可见显示器。状态先报 `LOGIN_REQUIRED`。
3. 员工在 Edge 里自己点「商标综合查询」，完成 SSO / 验证码。
4. **我已登录，检查并进入查询** → `connect_browser`。不要直接 `goto /sgtmi`（会被网站拦截），必须从首页点网站自己的「商标综合查询」。
5. 状态到 `READY` 后 **开始查询** → `start`。专用 Edge 移到屏幕外继续渲染，不抢前台。
6. 单条临时失败先跳过，全部跑完再自动重试一轮。只有员工点「暂停任务」才会整批暂停。
7. 完成后 **另存结果**。工作副本已经在本机任务目录；另存为只是复制，且禁止覆盖原始输入文件。

任务期间不要把登录失效、验证码、瞬时 403 自动升级成整批暂停（这是 0.1.5 之后的产品规则）。失败写入该行和「查询执行记录」工作表。

## 5. 业务规则（改查询结果前必读）

规则源码在 `worker/src/trademark_worker/selection.py`，规格在 `docs/superpowers/specs/2026-09-09-trademark-query-desktop-design.md` 第 10、11 节。不要凭感觉做模糊匹配。

### 5.1 共同规则

- 商标比较：Unicode NFKC、压缩空白、不区分大小写后必须完全一致。
- 申请人比较：同样标准化；**不删除**「有限公司」等主体字样，不做工商推断。
- 空白商标行不发起查询。
- 原始文件只读复制后再写；只读属性的源文件要把工作副本改成可写，否则 `os.replace` 会 WinError 5。

### 5.2 商标申请查询

- 检索要素填商标；申请人含汉字填中文字段，否则填英文字段。
- 结果里商标和申请人都匹配后，按网站「序号」**从大到小**点详情。
- 必须点商标名称/图样单元格进详情，不要把申请/注册号链接当默认入口。
- 详情必须有专用权期限才采用；没有则试下一条。全都没有则记「未找到有效专用权期限」，不要编数据。

### 5.3 唯一性查询

- 只填检索要素，不填申请人。
- 必须翻完全部分页，不能只看第一页。
- 同名行逐条裁剪后按页面顺序纵向拼接，插入截图列。
- 标准化后申请人只有一家 →「是」；多家 →「否」；没有同名 →「未检索到同名商标」；申请人为空 →「需人工复核」。
- 「否」时申请人和专用权期限留空。「是」时可填唯一申请人原文；期限仅在按申请查询规则进详情验证成功后才填。

### 5.4 浏览器就绪

`READY` 不能只看 `/sgtmi` 上有没有检索表单。CNIPA 会先画出公开查询壳，过一段时间再跳 SSO。判定要同时看到页头里的已登录账号名。员工点过「我已登录」且已经由首页导航进入 `/sgtmi` 时，`runtime.py` 有额外放行，因为页头用户名有时不可靠。

SSO 用户信息页（`sso.cnipa.gov.cn`）**不等于**已经可以查商标。必须回到商标网并进入综合查询。

## 7. 开发环境

需要：

- Windows 10/11
- Python **3.11**（不要 3.12+，`pyproject.toml` 已限制）
- Node.js / npm
- Rust MSVC 工具链
- Visual Studio C++ Build Tools
- 本机 Microsoft Edge
- 虚拟环境在 `worker\.venv`，不在仓库根目录

首次准备 Worker：

```powershell
py -3.11 -m venv worker\.venv
worker\.venv\Scripts\python.exe -m pip install -e "worker[dev]"
```

启动桌面开发版：

```powershell
cd apps\desktop
npm install
npm run tauri -- dev
```

注意：

- Vite 必须忽略 `src-tauri/**`，否则会监视 Rust 构建输出并在 Windows 上 EBUSY。
- 发版前停掉正在跑的 `tauri dev` / Vite，否则 `npm ci` 可能删不掉被占用的原生模块。
- 前端和 Rust 命令都要从 `apps/desktop` 跑，不要在仓库根目录执行 `npm test`。
- Worker 控制台进程用 `CREATE_NO_WINDOW`，安装版不会弹出黑框。

## 10. 现场排障

更完整的案例在 `.learnings/ERRORS.md` 和 `.learnings/LEARNINGS.md`。下面是员工侧最常见的情况。

| 现象 | 原因与处理 |
| --- | --- |
| 提示已有客户端在运行 | 单实例锁。关掉旧窗口，不要再开一个。 |
| 0.1.9「后台截图服务未能启动」，但 Edge 已经打开 | 升级到 0.1.10。新版会等真实 Edge 根进程并接回已打开的专用窗口，不必清登录资料。 |
| 已经登录仍不能开始查询 | 确认从首页点了「商标综合查询」；SSO 用户信息页不够。再点「我已登录」。 |
| 打开网站后看不到登录页 | 专用 Edge 可能在屏幕外。0.1.9+ 会尝试拖回可见显示器；仍看不见就用任务栏把 Edge 拖回来。 |
| 查询时抢焦点 / 一切换窗口就停 | 这是旧行为。当前设计是任务开始后 Edge 在屏幕外继续跑。若复现，查是否误调了 `set_focus` 或 `restore_for_user`。 |
| 唯一性长结果页裁剪失败「不在后台截图范围内」 | 行要先 `scrollIntoView` 再按视口坐标裁。`background.py` 已按此改，大表仍需用真实多页样例回归。 |
| 结果 XLSX 写失败 WinError 5 | 源文件只读。只把工作副本去掉只读，不要改员工原件。 |
| 关闭客户端后 Edge 还在 | 正常关闭应发 `shutdown` 并等 Worker。若残留，结束命令行带本应用 `edge-profile` 的 `msedge.exe`，不要杀员工自己的 Edge。 |
| 开发构建 EPERM / EBUSY | 先停 Vite/tauri dev 再发版。 |
| 测试找不到 Python 包或虚拟环境 | 用 `worker\.venv`，不要用仓库根 `.venv` 或系统 Python。 |

浏览器 PID：Edge 启动进程可能会退出，再由新的根进程接管。必须以 `--user-data-dir=` 精确匹配专用 profile，并排除带 `--type=` 的子进程。见 `browser/edge.py`。

截图：不要用 HWND/桌面截图。最小化或被挡住时 Win32 截图会得到全黑但尺寸正确的 PNG。必须走回环 CDP，`fromSurface=false`，并拒绝黑帧。

## 12. 硬约束（不要做）

这些是产品和合规边界，不是技术欠债：

- 不要自动填登录表、不要读验证码、不要绕 WAF、不要上代理/改指纹、不要加 `--enable-automation`。
- 不要对网站做高并发或循环猛刷 `about:blank`。
- 不要把 BuddyAgent 接回来，也不要为了「复用」去改那个仓库。
- 不要在查询过程中把专用 Edge 拉回前台，除非员工点了「打开商标网站」。
- 不要缩小证据 PNG 去迁就 Excel 行高；嵌原图像素，只限制显示高度（上限 409 磅）。
- 不要在日志或协议里输出 Cookie、账号、密码、验证码、完整页面存储。
- 不要把安装包发到不可控的外部渠道；内置 API Key 对安装用户不是绝对保密。
