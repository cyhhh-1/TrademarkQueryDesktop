# 商标查询助手后台稳定执行设计

## 目标

把当前可演示的单机流程升级为可交付给普通员工使用的稳定批量工具。任务开始后，员工可以最小化客户端并继续使用其他软件或自己的浏览器；查询程序不得抢占前台、不得因页面瞬时变化中止整批任务，并且无论成功多少条都必须产生可保存的 XLSX 结果。

## 强制约束

- CNIPA 登录只在开始任务前作为准入条件检查一次。
- 任务运行期间不再把登录、验证码、页面跳转或超时转换为整批自动暂停。
- 只有用户可以主动暂停；暂停在当前安全步骤结束后生效。
- 单条异常先跳过，首轮结束后自动重试一次；第二次仍失败则记录失败并继续完成任务。
- 每处理完一条都保存工作副本和检查点，程序异常退出后仍保留阶段性结果。
- 客户端和专用 Edge 均不得在查询过程中主动抢占键盘焦点或跳到前台。
- 任务完成、部分失败或用户取消时发送 Windows 系统通知。
- 任务完成后不关闭专用 Edge。
- 原 BuddyAgent 项目不做任何修改。

## 浏览器执行模型

保留真实 Microsoft Edge、独立用户目录和 Windows UI Automation，不启用 WebDriver，不修改登录流程。Edge 仅开放随机端口、仅监听 `127.0.0.1` 的 DevTools 截图通道，并且不使用 `--enable-automation`；该通道只从既有 CNIPA 标签页读取渲染像素。新增“程序拥有的标签页”管理层：每一步操作前按标签标题和 CNIPA URL 重新定位查询、结果或详情标签；员工切换到其他应用、其他窗口或自己的浏览器不会改变任务状态。如果程序拥有的临时结果/详情标签丢失，本条查询按可重试异常处理，不暂停整批任务。

UIA 操作本身不调用 `set_focus`。任务开始时专用 Edge 自动最小化；证据截图由本机 DevTools 协议直接从页面渲染层获取整页图，再根据 UIA 文档坐标裁剪，不读取桌面画面，也不会因为窗口最小化或被遮挡产生黑图。捕获失败时本条进入重试队列。员工可以继续使用普通 Edge 窗口或其他浏览器处理自己的工作；只有主动点击“打开商标网站”时才恢复专用 Edge。

## 翻页

页码以页面真实显示的“当前页 / 总页数”为准，不再只依赖进程内 `_page_number`。翻页优先点击可见数字；数字不在当前分页组时点击 `>` 或 `<`，必要时使用 `>>` 或 `<<`。每次点击后同时验证当前页文本和结果表指纹发生变化，失败则有限次数重试。搜索、详情回跳和唯一性截图均使用同一套翻页器。

## 容错批处理

任务引擎维护首轮队列和重试队列。每条成功、未找到或最终失败都形成 `TaskItemResult`。`NeedsUserAction`、UIA 暂时不可用、页面超时、截图失败和单条解析异常统一视为该条可重试错误，不再返回 `paused_user_action`。

首轮失败项在其余商标完成后进入第二轮。第二轮仍失败时写入最终失败结果。输出工作簿保留原模板字段，并新增“查询执行记录”工作表，记录原行号、商标、最终状态、尝试次数和说明。这样成功结果仍写入原列，失败项也有明确可追溯结果。

用户点击“暂停”时设置协作式暂停标志；当前不可分割的 UIA 操作结束后保存检查点并进入用户暂停状态。点击“继续”后从当前队列继续。用户点击“取消”时同样先安全落盘，再结束为可保存的阶段性结果。

## 客户端行为

- 修复无边框窗口所需的最小化、最大化、关闭和拖动权限。
- 标题栏空白区域支持拖动，双击切换最大化；按钮区域不触发拖动。
- 查询运行时显示当前商标、首轮/重试轮次、当前页/总页数、完成数、失败数、用时和预计剩余时间。
- 将运行阶段的“重新检测”移除；登录检测仅保留在开始任务前。
- 增加“暂停任务”和“继续任务”按钮。
- 完成通知不激活窗口，只显示 Windows 通知；通知文本包含成功数和失败数。

## 验收标准

1. 三条以上申请查询可以连续执行，单条失败不会阻断后续商标。
2. 唯一性查询可以遍历至少五页结果并返回第一页到最后一页的所有同名记录。
3. 查询时最小化客户端、用其他窗口覆盖 Edge、使用普通浏览器，任务仍继续且不会抢焦点。
4. 首轮失败项在末尾自动重试一次，最终始终生成 XLSX；执行记录工作表包含所有输入行。
5. 任务结束后 Edge 仍然运行，客户端显示完成状态并发送 Windows 通知。
6. 最小化、最大化、关闭、拖动和双击标题栏均通过安装版原生窗口验收。
