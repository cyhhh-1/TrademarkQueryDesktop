# 商标查询桌面客户端设计规格

- 日期：2026-09-09
- 项目：TrademarkQueryDesktop
- 版本：首版（完全本地运行）
- 状态：待用户确认后进入实施计划与编码

## 1. 目标

建设一个完全独立的 Windows 桌面应用，供员工在自己的电脑上完成国家知识产权局商标查询。员工在同一个应用中选择 XLSX、打开专用 Microsoft Edge、手动登录、启动自动查询、查看进度，并将带查询信息和截图的结果 XLSX 另存到本机。

首版支持两类输入：

1. `商标申请.xlsx`：按商标和申请人查询，选择符合规则的商标详情，填写申请人、专用权期限并插入详情页截图。
2. `商标查询是否唯一性.xlsx`：按商标查询全部同名记录，判断申请人是否为同一公司，填写唯一性结果，并将所有同名记录的裁剪图纵向拼接后插入表格。

## 2. 隔离边界与非目标

新项目位于 `D:\4.29\TrademarkQueryDesktop`，拥有独立源码、依赖、构建配置、Git 仓库和运行目录。现有 `D:\4.29\BuddyAgent_2026.8.12` 在本项目实施期间保持只读。

新程序可以复制已经验证过的查询算法和字段规则，但运行时不得导入、软链接或调用 BuddyAgent 中的 `.agents/skills/trademark-query`、后端、前端、数据库、MQTT 或其他服务。

首版明确不包含：

- BuddyAgent 后端接入、SOP 接入或技能注册；
- 数据库、对象存储、MQTT、大模型或云端任务历史；
- 用户体系和应用内账号登录；
- CNIPA 账号密码、验证码的读取、保存或自动填写；
- 随系统启动、后台常驻、自动上传或自动更新；
- 同一台电脑同时执行多个商标任务。

因此首版不会改变当前项目的任何功能、技能、SOP、依赖或部署方式。

## 3. 总体架构

```text
员工
  |
  v
Tauri 2 桌面壳 + Vue 3 页面
  |  启动/停止、状态与进度、文件选择与另存为
  |  stdin/stdout NDJSON
  v
Python Worker（PyInstaller onedir sidecar）
  |  Playwright 通过本机回环 CDP 连接
  v
专用可见 Microsoft Edge
  |  员工手动登录，Worker 只观察登录状态
  v
国家知识产权局商标查询网站

Python Worker
  +-- openpyxl：读取和写入 XLSX
  +-- Pillow：裁剪、拼接和压缩截图
  +-- checkpoint：逐行保存进度并支持恢复
```

### 3.1 桌面界面

Tauri 2 负责 Windows 原生窗口、文件选择、另存为、进程管理和本地路径权限。Vue 3 负责页面、任务状态和进度展示。

### 3.2 查询 Worker

Python Worker 负责：

- 校验和识别 XLSX 模板；
- 启动或连接专用 Edge；
- 识别网站、登录、拦截和查询状态；
- 执行两类查询业务规则；
- 截图、裁剪、拼接和写回 XLSX；
- 保存逐行检查点；
- 通过 NDJSON 向桌面界面发送结构化事件。

Worker 使用 Python 3.11 和 PyInstaller `onedir` 方式打包为独立 sidecar。选择 `onedir` 是为了降低单文件临时解压、启动慢和杀毒软件误报的风险。运行机器不需要另装 Python。浏览器使用机器已安装的 Microsoft Edge，不打包 Chromium。

### 3.3 Microsoft Edge

程序使用专用、可见的 Edge 用户数据目录，不接管员工日常 Edge 配置。应用只在员工点击“打开商标网站”后启动 Edge，初始地址固定为：

`https://wcjs.sbj.cnipa.gov.cn/`

Edge 通过仅监听 `127.0.0.1` 的动态 CDP 端口供 Worker 连接。登录、账号密码和验证码均由员工在 Edge 内自行操作。Worker 可以观察页面和 URL，但在 SSO 或验证码页面不得输入、点击或读取凭据。

## 4. 本地目录和数据

运行数据统一放在：

`%LOCALAPPDATA%\TrademarkQueryDesktop\`

```text
TrademarkQueryDesktop/
  edge-profile/                 # 专用 Edge 登录会话和 Cookie
  settings.json                 # 非敏感本机设置
  logs/                         # 脱敏运行日志
  tasks/
    <run_id>/
      input/                    # 输入文件的只读副本
      output/                   # 自动生成的结果文件
      evidence/                 # 原始截图、裁剪图和拼接图
      request.json              # 任务类型、输入映射和开始时间
      checkpoint.json           # 逐行检查点
      result.json               # 完成状态与结果摘要
```

约束：

- 原始 XLSX 永不原地修改；Worker 先复制到任务目录再处理。
- 输出先写临时文件，关闭并校验可重新打开后再原子改名为最终文件。
- “另存为”由 Tauri 将已校验结果复制到员工选择的位置。
- 如果目标文件已存在，必须由员工明确确认覆盖。
- 不在日志中记录 Cookie、账号、密码、验证码或完整页面存储内容。
- 员工可在界面中打开任务文件夹或删除已完成任务的本地缓存；专用 Edge 登录资料单独保留，除非员工选择“清除登录会话”。

## 5. 用户流程

1. 员工启动商标查询桌面客户端。
2. 员工拖入或选择 XLSX。
3. 程序识别模板类型、工作表、表头和待处理行；无法可靠识别时不启动查询，并明确列出缺失字段。
4. 员工点击“打开商标网站”。程序启动专用 Edge 并打开 CNIPA 首页。
5. 如需登录，员工在 Edge 中点击“商标综合查询”，自行完成账号、密码和验证码。程序持续被动观察页面状态。
6. 页面回到 CNIPA 首页或进入综合查询页后，程序验证是否确实到达可查询状态。
7. “开始查询”按钮可用，员工启动任务。
8. 程序逐行查询、展示当前商标、行号、阶段、成功或失败原因，并在每行完成后保存检查点。
9. 登录过期、验证码、`about:blank`、403 或 406 时，任务自动暂停，不丢失已完成结果；员工恢复网站后点击“继续”。
10. 完成后程序校验结果 XLSX，显示统计信息。员工点击“另存为”自行选择保存路径，也可以打开本地任务文件夹检查截图。

## 6. 页面与交互

首版采用单窗口、分阶段界面：

### 6.1 文件区

- 拖放区域和“选择 XLSX”按钮；
- 文件名、模板类型、工作表、总行数和待处理行数；
- 校验错误与可操作的修复提示；
- 重新选择文件。

### 6.2 浏览器区

- Edge 状态：未启动、等待网站、需要登录、已回首页、可查询、需要验证码、被拦截；
- 当前 URL 只显示域名和安全分类，不在普通日志中持久化查询参数；
- “打开商标网站”“重新检测”“清除登录会话”按钮；
- 清除登录会话会删除专用 Edge 配置中的登录数据，属于显式操作，执行前二次确认。

### 6.3 任务区

- “开始查询”“继续”“取消”按钮；
- 总进度、成功数、失败数、暂停原因；
- 每行显示：表格行号、商标、当前阶段、结果和错误摘要；
- 取消任务只停止后续查询，保留已完成数据和检查点。

### 6.4 完成区

- 输出文件名、完成时间、成功/失败统计；
- “另存为”“打开任务文件夹”“查看失败项”按钮；
- 失败项可以在同一任务内重试，已成功项默认跳过。

## 7. 浏览器和登录状态机

浏览器状态如下：

```text
EDGE_NOT_RUNNING
  -> WAITING_SITE
  -> LOGIN_REQUIRED
  -> RETURNED_HOME
  -> READY
  -> RUNNING

任意在线状态
  -> CAPTCHA_REQUIRED
  -> AUTH_BLOCKED
  -> WAF_BLOCKED
  -> PAUSED_USER_ACTION
  -> READY（员工处理后恢复）
```

判定规则：

- `EDGE_NOT_RUNNING`：未找到本项目启动且带专用 profile 的 Edge 进程或 CDP 端点。
- `WAITING_SITE`：Edge 已连接，但尚未识别出 CNIPA 页面。
- `LOGIN_REQUIRED`：主机为 `sso.cnipa.gov.cn`，或页面具有登录表单/验证码的稳定特征。
- `RETURNED_HOME`：主机为 `wcjs.sbj.cnipa.gov.cn` 且路径为 `/` 或首页，但尚未进入可查询表单。
- `READY`：地址为 `/sgtmi`，同时存在“检索要素”和“查询”控件，页面连续稳定至少 2 秒。
- `CAPTCHA_REQUIRED`：页面出现验证码控件或网站要求人工验证。
- `AUTH_BLOCKED`：页面为 `about:blank`，或从 SSO 导航后变为空白页。
- `WAF_BLOCKED`：HTTP 403/406，或页面正文包含网站拒绝/访问异常的稳定特征。

安全与恢复规则：

- 程序不得把“URL 看起来正确”当作已登录，必须同时验证查询表单。
- 开始任务前、每次新查询前、结果页跳转后和详情页跳转后都重新校验状态。
- 登录失效时停止自动操作并保存检查点，由员工手动完成登录或回到网站。
- `about:blank` 不自动循环刷新或高频重试；界面提示员工关闭当前空白页，再由“打开商标网站”从官网首页重新进入。
- 对 403/406 采用停止并提示，不使用代理、伪造指纹、绕过验证码等规避措施。
- 检测采用低频事件监听和温和轮询，禁止对网站做高并发请求。

## 8. 任务状态机和恢复

```text
DRAFT
  -> WAITING_BROWSER
  -> READY
  -> RUNNING
  -> COMPLETED

RUNNING
  -> PAUSED_USER_ACTION
  -> RUNNING
  -> FAILED
  -> CANCELLED
```

每完成一行后，Worker 必须：

1. 保存该行结构化结果和证据文件路径；
2. 写入工作副本 XLSX；
3. 验证工作簿可以重新打开；
4. 原子更新 `checkpoint.json`；
5. 再处理下一行。

应用或电脑异常退出后，重新打开同一任务可以从最近一个已验证检查点继续。恢复时会核对输入文件指纹、模板类型和已生成证据，防止把检查点应用到其他文件。

## 9. XLSX 模板识别与通用规则

- 只接受 `.xlsx`，拒绝带宏的工作簿作为首版输入。
- 通过标准化后的表头名称识别模板，不依赖固定列号。
- 标准化包括：去除首尾空格、全角/半角空格统一、换行归一和常见表头别名映射。
- 必须保留输入工作簿原有工作表、样式、合并单元格和非目标列；仅写入目标字段和图片。
- 空白商标行跳过并记录为输入问题，不发起网站查询。
- 图片锚定到对应商标行的截图目标列；按列宽和预设最大宽度等比例缩放，行高随图片调整。
- 如果模板已有目标单元格内容，默认不覆盖并提示员工；员工可以在任务开始前勾选“覆盖已有结果”。
- 单项查询失败不终止整个文件，记录原因后继续下一行；系统性登录或拦截错误则暂停全任务。

## 10. 模式一：商标申请查询

### 10.1 查询输入

- “检索要素”填写待查询商标。
- 申请人是中文名称时填写“申请人名称（中文）”。
- 申请人是英文或其他拉丁字符名称时填写“申请人名称（英文）”。
- 中文/英文判定以名称是否包含汉字为主；混合名称优先填中文字段，并在日志中记录判定结果。

### 10.2 结果筛选

- 只保留页面中商标文字经空白和大小写标准化后与检索要素完全相同的记录。
- 申请人名称也必须经空白、括号和全半角标准化后匹配输入申请人。
- 如有多个符合记录，按照网站“序号”从大到小依次尝试，优先点击序号靠后的记录。
- 必须点击结果表中商标名称/图样所在单元格进入详情页，不把申请/注册号链接作为默认入口。
- 若首选详情页无“专用权期限”，返回结果页继续尝试下一个序号，直到找到同时具备匹配申请人和专用权期限的详情。
- 若所有匹配记录均无专用权期限，结果记为“未找到有效专用权期限”，保留候选信息和失败证据，不臆造数据。

### 10.3 详情提取和输出

详情页至少校验并提取：

- 商标名称；
- 申请/注册号；
- 国际分类；
- 申请人名称（中文或英文）；
- 专用权期限；
- 商标状态（用于校验和结果说明）。

截图规则：

- 等待详情核心字段稳定显示后截图；
- 截取完整详情内容区域，必要时使用整页截图，不能只截浏览器可见顶部；
- 截图应包含商标、申请人和专用权期限；
- 原图保存到任务证据目录，并将可读尺寸版本插入对应 XLSX 行。

输出规则：

- 将网站详情中的申请人名称写入模板对应字段；
- 将专用权期限按网站原文写入对应字段；
- 将详情截图插入对应商标的截图字段；
- 另行保存结构化来源信息，便于失败重试和审计。

## 11. 模式二：商标唯一性查询

### 11.1 查询和翻页

- 只填写“检索要素”，不填写申请人字段。
- 遍历查询结果全部分页，而不是只处理第一页。
- 对每页逐条读取商标文字，只选择标准化后与检索要素完全相同的记录。
- 每条同名记录保存序号、申请/注册号、国际分类、申请日期、商标和申请人名称。

### 11.2 单条裁剪与拼接

- 每一条完全同名记录单独截取结果表中的完整行。
- 裁剪图必须包含该行的序号、申请/注册号、国际分类、申请日期、商标和申请人名称。
- 保留页面缩放比例，避免截图文字模糊。
- 按页面顺序将全部裁剪图纵向拼接，图片之间使用统一的小间距和浅色分隔线。
- 拼接图过高时仍保存一张完整原图；插入 XLSX 时按最大宽度等比缩放并调整行高，确保可查看全部内容。

### 11.3 唯一性判断

申请人名称按以下规则标准化：

- Unicode 规范化；
- 去除首尾和重复空白；
- 统一全角/半角字母、数字和括号；
- 英文字母不区分大小写；
- 不擅自删除“有限公司”“股份有限公司”等主体类型文字；
- 不进行工商主体推断或模糊合并。

判断：

- 找到一条或多条完全同名商标，且标准化后的非空申请人名称只有一个：唯一性写“是”。
- 找到完全同名商标，且标准化后的非空申请人名称超过一个：唯一性写“否”。
- 未找到完全同名商标：写“未检索到同名商标”，不将其误判为“是”。
- 记录中申请人为空或无法读取：写“需人工复核”，不自动判断。

输出：

- 无论结果是“是”还是“否”，都插入包含全部同名记录的纵向拼接图。
- 结果为“否”时，申请人和专用权期限字段保持空白。
- 结果为“是”且模板要求申请人时，可填写唯一的标准化前申请人原文。
- 结果为“是”且模板要求专用权期限时，再按模式一的候选选择规则进入详情；只有成功验证后才填写期限。

## 12. Worker 通信协议

桌面壳与 Worker 使用一行一个 JSON 对象的 NDJSON。标准输出只允许协议消息，诊断日志写标准错误或本地日志文件。

命令示例：

```json
{"type":"start","run_id":"...","input_path":"...","mode":"application"}
{"type":"resume","run_id":"..."}
{"type":"cancel","run_id":"..."}
```

事件示例：

```json
{"type":"hello","protocol":1,"worker_version":"0.1.0"}
{"type":"browser_state","state":"LOGIN_REQUIRED","message":"请在 Edge 中完成登录"}
{"type":"row_progress","row":5,"mark":"示例商标","stage":"opening_detail"}
{"type":"paused","reason":"AUTH_BLOCKED","recoverable":true}
{"type":"completed","output_path":"...","success":8,"failed":1}
{"type":"error","code":"TEMPLATE_MISSING_HEADER","message":"缺少唯一性结果列"}
```

协议要求：

- 消息包含协议版本，桌面壳发现版本不兼容时拒绝启动任务。
- 错误包含稳定错误码、员工可读中文说明和是否可恢复。
- 不通过协议传输网站凭据或 Cookie。
- Worker 异常退出时，Tauri 显示最后日志摘要，并允许从检查点恢复。

## 13. 错误处理

错误分为三类：

1. 输入错误：模板无法识别、缺列、文件损坏、文件被 Excel 锁定。查询前阻止启动并给出修复提示。
2. 可恢复运行错误：登录过期、验证码、`about:blank`、403/406、短时导航失败。保存检查点并等待人工处理。
3. 单行数据错误：未找到精确商标、无有效期限、详情字段不完整、截图失败。记录本行失败后继续其他行，并支持完成后单独重试。

重试要求：

- 页面导航失败采用有限次数、递增等待的低频重试。
- 登录和 WAF 类错误不自动反复重试。
- 同一行重试前清理临时证据，不覆盖已经验证的成功证据。
- 所有失败都必须在结果摘要中可见，禁止静默跳过。

## 14. 安全和隐私

- 应用不接触 CNIPA 账号密码和验证码。
- 登录 Cookie 仅存在专用 Edge profile 中，不上传、不复制到任务目录。
- CDP 只绑定本机回环地址，端口动态分配，不暴露到局域网。
- 页面截图、XLSX 和日志全部保存在员工电脑。
- 日志默认脱敏申请/注册号和路径中的用户名；员工可以主动导出诊断包，导出前展示包含内容。
- 退出应用时终止 Worker；Edge 只在由本应用启动且员工选择关闭时才关闭，避免误关其他 Edge 窗口。
- 不采用绕过验证码、代理池、指纹伪装或高并发抓取。

## 16. 测试策略

### 16.1 单元测试

- 两类模板识别、表头别名和缺列错误；
- 中文/英文申请人字段选择；
- 精确同名规则、申请人标准化、唯一性判断；
- 候选按序号倒序和“无期限继续尝试”规则；
- 图片裁剪、纵向拼接和 XLSX 图片锚定；
- URL/DOM 状态分类，包括 SSO、首页、`/sgtmi`、验证码、`about:blank`、403 和 406；
- 检查点原子写入、输入指纹校验和恢复。

### 16.2 集成测试

- 使用本地脱敏 HTML 模拟查询列表、分页和详情页，不访问真实网站；
- 模拟 Worker 与 Tauri 的 NDJSON 通信、异常退出和恢复；
- 校验输出 XLSX 可由 Excel 打开、字段正确且图片存在；
- 验证原始 XLSX 内容和修改时间不变。

### 16.3 真实环境验收

- 在专用 Edge 中由员工手动完成一次登录；
- 从 CNIPA 官网首页进入综合查询，验证回到首页、进入 `/sgtmi` 和 `about:blank` 等状态提示；
- 用真实 `商标申请.xlsx` 完成整份文件，逐行核对申请人、期限和详情截图；
- 用带表头的真实 `商标查询是否唯一性.xlsx` 完成整份文件，核对全部分页、所有同名行、公司判断和纵向拼接图；
- 查询中途退出应用，再次启动后恢复；
- 登录过期时暂停，员工重新登录后继续；
- 在一台未安装 Python、只安装 Edge 和 Excel/WPS 的干净 Windows 机器上执行安装与冒烟测试。

真实网站验收采用人工触发和低频查询，不将实时网站作为自动化测试流水线依赖。

## 17. 验收标准

满足以下条件才视为首版完成：

- 产出可安装的 Windows 桌面客户端，运行机器无需 Python、Node.js 或 BuddyAgent；
- 员工能在同一客户端中选择 XLSX、打开专用 Edge、看到登录状态、开始/暂停/继续任务并另存结果；
- 两类 XLSX 的业务规则全部实现，且整份文件能完整跑通；
- 模式一的详情必须通过点击商标名称/图样进入，候选按序号倒序并验证专用权期限；
- 模式二遍历所有分页，裁剪所有完全同名记录并纵向拼接，唯一性判断符合申请人规则；
- 原始输入文件永不被覆盖，输出 XLSX 能正常打开且截图锚定到对应行；
- 登录过期、验证码、`about:blank`、403 和 406 均会安全暂停并可恢复；
- 异常退出后可以从最近一条已验证记录恢复；
- 所有数据和截图仅保存在本机，员工自行另存；
- 不修改、不依赖、不影响 `BuddyAgent_2026.8.12` 的代码、配置、数据库、技能、SOP 或服务；
- 自动化测试通过，并完成两份真实模板的人工验收记录。

## 18. 后续扩展边界

未来如需中央任务、MQTT、多机调度、统一账号、对象存储或 BuddyAgent 技能调用，应作为独立的第二阶段设计，通过版本化本地协议接入。首版不预埋对现有项目的源码依赖，只保留稳定的任务 JSON 和 Worker 协议扩展点。
